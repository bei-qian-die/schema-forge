§ 02 — 需要先想清楚的四条链路

流程决定架构，架构决定你能讲多久

这四条链路画明白了，代码就是填空题。面试时也是按这四条讲，逻辑最顺。

A

引擎运行时链路

编译期 / 运行期分离 —— 能提前算的绝不留到运行时

  1. 迁移 migrate() 版本链 v1→v2→v3
  2. 解析 协议校验、默认值填充、key 全局去重
  3. 编译 每个表达式 → AST → 闭包 + deps 集合
  4. 建图 依赖图 → Kahn 拓扑序 + DFS 三色环检测
  5. 建仓 value / status / version 三棵树，扁平路径索引
  6. 交互 setValue → 脏值入队 → 沿反向边求下游闭包
  7. 校验 同步立即跑，异步防抖 300ms 且同 key 合并
  8. 提交 validateGate() 全量闸门 → serialize()

面试可讲：编译期/运行期分离是所有引擎的通用范式（Vue 模板编译、Babel、Vite 预构建都这么做）。

B

设计器编辑链路

不可变数据 + 增量补丁，为协同编辑预留通道

  1. 拖拽物料 → makeNode(type) 生成字段 + 默认 props
  2. diff 出 RFC 6902 JSON Patch（add/replace/move/remove）
  3. applyPatch 不可变应用，旧引用不变便于 time-travel
  4. pushUndo() 300ms 连续输入合并为一个撤销单元
  5. 增量重编译：只重编译受影响子树的表达式
  6. 画布按 version 位图精准重渲染 + Schema 面板同步高亮
  7. localStorage 自动保存（debounce 800ms，带版本号）

追问必答：为什么用 Patch 而不是直接改对象 —— 增量可传输，将来接 Yjs 做协同不用改架构。

C

联动配置链路

产品的灵魂，也是最容易做砸的一段

  1. 选中字段「纳税人识别号」，面板切到「联动」Tab
  2. 写规则：当 $form.invoice.type === 'COMPANY' 时 visible = true
  3. 解析器抽取依赖 → deps = ['invoice.type']
  4. 建边 invoice.type → taxNo.visible
  5. 拓扑排序得求值序；成环则红线报错并打印环路径
  6. 画布上画依赖连线，右侧可看 DAG 全景

可视化依赖图是面试现场最有杀伤力的一屏，务必做。

§ 04 — 唯一有技术壁垒的一段

表达式 → 依赖图 → 拓扑求值 → 精准传播

朴素做法：改一个输入框就把 500 个字段的 120 条联动全跑一遍，而且求值顺序取决于遍历序， 有环时静默算错。下面是解法。

packages/core/src/graph/toposort.ts
// 1. 建图：节点 = 字段路径，边 = dep → target
export interface DepGraph {
  nodes: string[]
  adj: Map<string, Set<string>>   // 正向：我影响谁
  rev: Map<string, Set<string>>   // 反向：谁依赖我
}

// 2. Kahn 拓扑排序：返回值不含的节点 ⇒ 环内节点
export function toposort(g: DepGraph) {
  const indeg = new Map(g.nodes.map(n => [n, 0]))
  for (const [, tos] of g.adj)
    for (const t of tos) indeg.set(t, (indeg.get(t) ?? 0) + 1)

  const q = g.nodes.filter(n => (indeg.get(n) ?? 0) === 0)
  const order: string[] = []

  for (let i = 0; i < q.length; i++) {
    const n = q[i]; order.push(n)
    for (const t of g.adj.get(n) ?? []) {
      const d = (indeg.get(t) ?? 0) - 1
      indeg.set(t, d)
      if (d === 0) q.push(t)
    }
  }
  return { order, cyclic: g.nodes.filter(n => !order.includes(n)) }
}

// 3. ★ 脏值传播：只重算下游闭包，且严格按拓扑序
export function propagate(
  p: string, g: DepGraph, order: string[], version: Map<string, number>
) {
  const down = new Set([p]); const stack = [p]
  while (stack.length) {                  // 反向 BFS 求闭包
    const cur = stack.pop()!
    for (const t of g.adj.get(cur) ?? [])
      if (!down.has(t)) { down.add(t); stack.push(t) }
  }
  const touched: string[] = []
  for (const n of order) {              // 顺序 = 拓扑序
    if (!down.has(n)) continue
    version.set(n, (version.get(n) ?? 0) + 1)
    touched.push(n)
  }
  return touched        // Vue 层只 patch 这些字段
}

    const chain: Migration[] = [
  { from: '1.0', to: '1.1', up: (s) => {
      // visibleWhen: {field,eq} → 表达式字符串
      return walk(s, n => n.visibleWhen
        ? { ...n, visible: toExpr(n.visibleWhen) }
        : n)
  }},
  { from: '1.1', to: '2.0', up: (s) => {
      // 平铺 fields → 支持 children 嵌套容器
      return nest(s)
  }},
]

export function migrate(schema: any) {
  let cur = schema
  for (const m of chain) {
    if (semverLt(cur.version, m.to)) {
      try { cur = m.up(cur); cur.version = m.to }
      catch (e) {
        // 迁移失败：保留原值并告警，绝不静默丢数据
        warn(`migrate ${m.from}→${m.to} failed`)
        break
      }
    }
  }
  return cur
}

    和 Formily / amis 有什么区别？

    Formily 是响应式表单框架、强绑 React；amis 是页面配置器。我把 Schema 当源码编译 —— core 零框架依赖、可换渲染层，且额外有依赖图/环检测/版本迁移链/精准传播这套编译期能力。一句话：它们是"框架"，我是"编译器"。

    为什么不用 new Function / eval？

    两个硬伤：一是 CSP unsafe-eval 环境（政企内网很常见）直接白屏；二是无法从字符串精确抽依赖，只能正则猜，字段 key 里有变量时必漏。自研 parser 顺带解决了报错行列定位和 AST 复用。

    循环依赖怎么处理？

    建图后跑 Kahn 拓扑，剩余节点即环内节点；再用 DFS 三色标记（white/gray/black）回溯调用栈打印完整环路径，在设计器里红线报错并给出字段名。绝不静默算错，也不允许栈溢出。

    精准更新具体怎么落地到 Vue？

    core 维护一个 Uint32Array 版本号位图，字段 key → 下标有稳定映射。传播时只 bump 下游闭包对应下标；Vue 侧 FieldNode.vue 用 computed 只订阅自己下标的 version，version 没变则 diff 直接跳过，不会触发子组件 render。

    大表单卡顿有三个来源，怎么分别解决？

    ① 全量重算 → 依赖图 + 精准传播（500 字段样本里 120 条 effect 降到 2 条）；② 全量渲染 → 尚未做虚拟滚动，这是已知缺口，不宣称 DOM 优化；③ 校验风暴 → 同步规则立即跑、异步规则防抖 300ms（站点配置 420ms）且同 key 请求合并。只有①有实测数字。

    撤销重做为什么用 JSON Patch？

    Patch 是最小增量、可序列化、可传输。直接存整份 Schema 快照 200 步会迅速膨胀；Patch 栈只存增量。更重要的是：将来接 Yjs 做多人协同时，网络上传的本来就是 Patch，不用改架构。

    Schema 升级后老数据崩了怎么办？

    migrate 迁移链：v1.0→v1.1→v2.0 逐级纯函数，跑完写回 version 字段。任一级抛错则保留原值 + 告警，绝不静默丢数据。这个设计点通常能换来面试官一句"你还想到了版本演进"。
